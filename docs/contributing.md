# 参与维护手册

手册应随着平台软件、路径、分区和使用流程的变化持续更新。

## 添加新页面

1. 在合适的 `docs/` 子目录创建 Markdown 文件。
2. 使用清晰的标题和简短章节。
3. 代码块注明语言，命令前说明执行位置和前提。
4. 在 `mkdocs.yml` 的 `nav` 中加入页面。
5. 本地运行 `mkdocs serve` 检查显示效果。
6. 运行 `mkdocs build --strict` 检查构建问题。
7. 提交 Pull Request 或按实验室约定审核后合并到 `main`。

## 建议的页面结构

```markdown
# 功能名称

一句话说明本页解决什么问题。

## 前提条件

说明权限、软件模块、目录或资源要求。

## 操作步骤

给出可以复制的命令，并解释需要修改的占位符。

## 常见问题

列出可验证的错误信息、排查命令和处理方法。
```

## 内容维护原则

- 不在公开文档中记录凭据、私钥、访问令牌或未获授权公开的基础设施信息。
- 不要把示例值描述成已在生产环境验证的配置。
- 涉及破坏性操作时，明确说明影响并优先给出安全的检查命令。
- 软件版本或路径变更时，搜索并更新所有相关页面。
- 对复杂操作记录最后验证日期和维护责任人。

## 本地检查

```bash
python -m pip install -r requirements.txt
mkdocs build --strict
```

GitHub Actions 会在推送到 `main` 后自动构建和部署；构建失败时，请先查看 Actions 日志。
